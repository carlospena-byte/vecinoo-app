# gates-app

- **Feedback messages:** always use `showGatesToast` (`lib/core/widgets/gates_toast.dart`, Figma "Toast"). Never use `SnackBar` / `showSnackBar` / `MaterialBanner`; `test/no_raw_snackbar_test.dart` fails if you do.
- **Pickers:** use the shared spinner time picker and shared calendar bottom sheet, never Material defaults.
- **Colors:** never hardcode colors; read semantic tokens via `context.palette` (`lib/core/theme/gates_palette.dart`, Figma "Vecinoo / Color" Light/Dark). Secondary text uses `context.gatesText`. Text on filled buttons uses `textOnBrand` / `textOnDanger`, not white. `test/no_hardcoded_colors_test.dart` and `test/theme_contrast_test.dart` enforce this.
- **Accessibility:** icon-only controls need a `tooltip`/`Semantics` label (`GatesAddButton` takes `semanticLabel`); tappable custom widgets wrap their content in `Semantics(button: true, …)` and expose `selected` when they can be selected; form fields announce their label (visible label text is wrapped in `ExcludeSemantics`); touch targets ≥ 44pt; layouts must not overflow up to 3x text (`test/text_scale_test.dart`, `test/accessibility_test.dart`).
- **Strings:** all user-visible text lives in `lib/l10n/app_es.arb` (template, locale `es`) and is read with `context.l10n.<key>` (`lib/l10n/l10n.dart`); run `flutter gen-l10n` after editing it. Keys are prefixed by feature (`visits…`, `amenities…`, `incidents…`, `auth…`, `session…`, `profile…`, `home…`, `common…`). Domain/data layers hold no UI text — labels are formatted in presentation with an `AppLocalizations` parameter. `test/no_hardcoded_strings_test.dart` enforces it.
- **Architecture:** per feature `domain/` (models + repository *interface*, no Flutter/Supabase types), `data/` (`Supabase…Repository` implementing it, every call through `guardFailure`, no `dart:io`), `presentation/` (screens render state; flows live in Riverpod `Notifier` controllers with immutable state + a one-off `events` stream; text controllers stay in the widget). Errors are typed (`lib/core/error/failure.dart`); show causes with `failureDetail`, never `catch (_)`. Controllers are tested with fake repositories (see `test/report_incident_controller_test.dart`).
- **Provider retries:** Riverpod 3 retries any thrown `Exception`; the app uses `providerRetry` (`core/error/provider_retry.dart`) so permanent `AuthFailure`s are not retried (retries refresh the router and used to drop the OTP screen's `extra`).
